# 数据库集合配置清单

> 目标：一次性完成 16 个集合的创建与权限配置，让小程序所有功能不再回退到假数据。
>
> **重要认知**：微信云数据库是文档型（NoSQL），**建集合只是建一个空容器，不需要预先定义字段、不需要建表结构**。字段由代码写入时自动产生。所以这件事的实际工作量很小——建 16 个空集合 + 设权限，约 10 分钟。

---

## 一、为什么要建这些集合

代码里通过 `db.collection('xxx')` 访问的集合共 **16 个**（已扫描全部 `cloudfunctions/` 与 `miniprogram/` 源码统计，非文档照抄）。

集合不存在时，`miniprogram/utils/cloud-api.js` 会捕获错误并回退到 `mock-data` 假数据，控制台输出类似：

```text
读取 posts 集合失败，已回退到本地演示数据：errCode: -502005 database collection not exists
```

**判断标准**：控制台不再出现 `-502005`，页面数据来自云端而非假数据。

---

## 二、创建顺序：按开发优先级分三批

### 第一批：核心闭环（5 个）

跑通「登录 → 浏览 → 发帖 → 私信」的最小链路，必须优先完成。

| 集合名 | 用途 | 写入方 | 前端是否直查 | 建议权限 |
|---|---|---|---|---|
| `users` | 用户资料、信用分、车次绑定 | `login` / `bindTrain` / `updateProfile` | 否 | 仅创建者可读写 |
| `posts` | 求助/帮助/话题帖子 | `createPost` | **是** | **所有用户可读** |
| `orders` | 接单与订单状态 | `acceptOrder` / `publisherAcceptOrder` | **是** | **所有用户可读** |
| `conversations` | 私信会话 | `createOrGetConversation` / `ensureConversation` | 兜底直查 | **所有用户可读** |
| `messages` | 私信消息 | `sendMessage` | 否 | 仅创建者可读写 |

> `users` 已完成创建（登录验证通过）。

### 第二批：信用与治理（6 个）

支撑信用分、举报、感谢墙、微信交换等信任机制。

| 集合名 | 用途 | 建议权限 |
|---|---|---|
| `reviews` | 互助完成后的评价 | 仅创建者可读写 |
| `reports` | 举报记录 | 仅创建者可读写 |
| `complaints` | 投诉与申诉 | **所有用户可读** |
| `blocks` | 拉黑关系 | 仅创建者可读写 |
| `thank_wall` | 公开感谢墙 | **所有用户可读** |
| `wechat_exchange_requests` | 微信联系方式交换申请 | 仅创建者可读写 |

### 第三批：通知与运营（5 个）

不影响核心功能，可最后补，缺失时仅相关页面降级。

| 集合名 | 用途 | 建议权限 |
|---|---|---|
| `notification_logs` | 订阅消息发送日志 | 仅创建者可读写 |
| `notification_settings` | 用户通知偏好 | 仅创建者可读写 |
| `subscribe_records` | 订阅授权记录 | 仅创建者可读写 |
| `promotions` | 热门推广/置顶 | 仅创建者可读写 |
| `admin_logs` | 管理后台操作日志 | 仅创建者可读写 |

## 三、权限为什么这样设置

这是最容易设错、也最难排查的一环，原因有两条：

**1. 写入全部走云函数，云函数拥有管理员权限，不受集合权限限制。**
所以「仅创建者可读写」不会影响发帖、发消息等写入操作。

**2. 部分读取由前端直接查询数据库，这些集合必须开放读权限。**
代码中 `miniprogram/utils/cloud-api.js` 有 6 处 `wx.cloud.database()` 直查，涉及：

| 行号 | 集合 | 场景 |
|---|---|---|
| 90 | `posts` | 首页信息流列表 |
| 146 | `posts` | 帖子详情 |
| 237 | `conversations` | 会话列表（云函数失败时的兜底） |
| 295 | `orders` | 订单详情 |
| 322 | `thank_wall` | 感谢墙列表 |
| 408 | `complaints` | 投诉列表 |

**如果把这些集合设成「仅创建者可读写」，用户会看不到别人发的帖子**，而且不会报错，只是列表永远为空——这种「静默失败」最难排查。

**私信内容（`messages`）刻意不开放读权限**，因为聊天内容只应通过 `getMessageList` 云函数在服务端鉴权后返回，不应允许前端任意查询。

## 四、核心集合的字段参考

不需要手动创建字段，以下仅供你理解数据结构、排查问题时对照。

### `posts`（由 `createPost` 写入）

```js
{
  type: 'help' | 'offer' | 'topic',
  title, description, images: [],
  trainNo, carriageNo, seatNo, location,
  publisherOpenid,
  publisherInfo: { nickname, creditScore, rankName },
  status: 'open' | 'resolved',
  resolved: false,
  createdAt, updatedAt
}
```

### `conversations`（由 `createOrGetConversation` 写入）

```js
{
  relatedType, relatedId, postId, orderId,
  participantIds: [], participantOpenids: [],
  publisherOpenid,
  peerName, peerAvatarText, peerRankName,
  relatedTitle, relatedSummary, relatedPath,
  lastMessage, lastMessageAt,
  unreadMap: { [openid]: number },
  status: 'active'
}
```

### `messages`（由 `sendMessage` 写入）

```js
{
  conversationId,
  senderId, senderOpenid, receiverId,
  content, contentType: 'text',
  isRead, read,
  riskStatus, riskKeywords,
  createdAt
}
```

### `users`（由 `login` 写入，已验证）

```js
{
  openid, nickname: '旅者', avatarText: '旅',
  creditScore: 60, creditLevelName: '可信任旅客',
  isAdmin: false, status: 'active',
  helpCount, topicCount, thankCount, monthlyCompletedCount,
  trainBinding: null,
  createdAt, updatedAt
}
```

## 五、索引（可选，现在可以不做）

数据量小的时候索引不是瓶颈。以下为后期优化参考：

| 集合 | 建议索引字段 |
|---|---|
| `posts` | `trainNo` + `status` + `createdAt` |
| `messages` | `conversationId` + `createdAt` |
| `conversations` | `lastMessageAt` |
| `orders` | `postId`、`publisherOpenid` |

> 控制台中 `_id` 与 `_openid` 索引由系统自动维护，无需手动添加。

## 六、完成后如何验证

### 1. 验证集合已全部创建
云开发控制台 → 数据库 → 集合列表，应显示 16 个集合名。

### 2. 验证权限正确
首页应当不再报 `-502005`，且帖子列表为空（而非显示假数据）。

判断真假数据的方法：真数据在 `posts` 集合里能看到对应记录；假数据在 `utils/mock-data.js` 里写死，数据库中是空的。

### 3. 验证写入链路
发布一条帖子后：
- `posts` 集合应新增一条记录，`publisherOpenid` 是你的 openid；
- `users` 集合中该用户的 `topicCount` 或相关计数应变化。

## 七、常见错误对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `-502005 database collection not exists` | 集合未创建 | 按清单创建 |
| 列表始终为空但不报错 | 集合权限过严，前端读不到 | 改为「所有用户可读」 |
| 写入成功但查询不到 | 云函数写入的数据无 `_openid`，被「仅创建者可读写」拦截 | 同上 |
| 集合名拼错（如 `user` / `users`） | 大小写或单复数不一致 | 严格按清单，全小写 |
