## 四、第三批队友必须做什么

### P0：必须完成

- 将 `conversations`、`messages` 权限恢复为“仅创建者可读写”。

- 把云存储路径保存到 `posts` 集合。
- 保证其他用户可以正常看到帖子图片。

#### 3. 完善订单闭环
- 订单状态继续完善：待确认、进行中、确认完成、取消订单。
- 根据订单状态控制按钮显示隐藏。
- 修复 `in_progress` 状态下仍显示接单按钮的问题。

## 六、第三批开发注意事项

1. 不要改动第二批已经验证通过的核心流程。
2. 私信、接单功能必须用两个账号测试。
3. 新增页面要在 `app.json` 注册。
4. **`project.private.config.json` 不要提交到 Git**，它存的是本机绝对路径，提交后队友会打不开项目。
   > ⚠️ 注意区分：`project.config.json`（无 private）**必须提交**，里面是 `appid`、`miniprogramRoot`、`cloudfunctionRoot` 等关键配置。两者只差一个词，别搞混。
5. 开工前先 `git pull`。
6. 云函数更新后必须重新部署。
7. **永远不要执行 `git push -f`**。如果 Git 提示需要 force push，说明远程有你没有的提交，正确做法是 `git pull` 合并。
8. 提交建议使用规范：
   - `feat:` 新增功能
   - `fix:` 修复问题
   - `docs:` 文档更新

## 九、第三批（P0）开发进展（2026-11-01）

### 已完成

1. **私信权限**：`cloud-api.js` 移除 `conversations` 前端直查兜底；`sendMessage` 增加会话成员校验与拉黑拦截。
2. **内容安全**：`createPost` 增加敏感词校验与 `msgSecCheck`（接口无权限时降级为词库校验），新增 `config.json` openapi 权限。
3. **信用分**：`updateProfile` 新用户初始 60 分；`confirmComplete` 只允许进行中订单、重复调用幂等、感谢墙使用真实昵称、同步信用等级名。
4. **订单状态机**：新增 `cancelOrder` 云函数（双方可取消待确认/进行中订单，帖子恢复开放）；订单详情按「角色 + 状态」显示按钮，状态文案中文化，删除前端伪造的 `pending_review`。

6. **匹配**：首页帖子查询增加车厢维度（同车次 + 同车厢）。
7. **兜底数据**：消息列表、订单详情、帖子详情、感谢墙、未读数在云函数失败时不再返回演示数据。
8. **消息保留**：新增 `cleanupMessages` 云函数与每日 03:00 定时触发器，删除 7 天前私信。
