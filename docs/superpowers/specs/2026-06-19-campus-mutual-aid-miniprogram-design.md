# 校园综合互助小程序需求规格说明书

## 1. 项目概述

校园综合互助小程序面向校内学生，提供快递代取、代办、课程互助、二手交易和兼职五类校园生活服务。所有学生身份相同，既可以发布需求，也可以接单、下单、报名和私聊沟通。

项目目标是构建一个完整的校园互助交易闭环：

```text
发布内容 -> 他人接单/下单/报名 -> 创建订单 -> 私聊协商 -> 发布者确认完成 -> 双方评价 -> 增加信誉分 -> 段位提升
```

第一版不接入真实支付。金额和报酬仅作为信息展示，实际结算由双方线下完成。平台通过轻量级防诈骗机制、聊天记录留痕、信誉分、投诉处理和管理员入口降低交易风险。

## 2. 产品定位

项目定位为校园综合互助平台，而不是单一跑腿工具。它覆盖学生常见的校园生活需求：

- 快递代取：帮助同学从驿站、快递柜或校门口取快递。
- 代办：帮助同学完成打印、送资料、买东西、排队等日常事务。
- 课程互助：提供课程答疑、资料分享、学习搭子、作业思路交流等互助服务。
- 二手交易：发布和浏览校内二手物品，支持下单后私聊沟通。
- 兼职：发布和报名校内外兼职信息，支持私聊联系。

平台重点突出三个能力：

- 校园服务聚合：把常见校园需求放在统一入口中。
- 任务协作闭环：从发布、接单、聊天、完成到评价形成完整流程。
- 信任机制沉淀：通过信誉分、段位、评价和投诉处理提升交易安全感。

## 3. 用户与角色

第一版中所有普通学生身份相同：

- 可以发布快递代取、代办、课程互助、二手商品和兼职信息。
- 可以接单、下单或报名他人发布的内容。
- 可以和交易相关用户私聊。
- 可以对完成的订单进行评价。
- 可以查看自己的信誉分和段位。

管理员不是独立后台用户，而是在小程序个人中心中显示管理员入口。只有 `isAdmin` 为 `true` 的用户可以进入管理员页面。

## 4. 功能模块

### 4.1 首页

首页承担聚合入口作用，包含：

- 顶部搜索框。
- 消息通知入口。
- 5 个服务入口卡片：快递代取、代办、课程互助、二手交易、兼职。
- 最新任务预览。
- 推荐兼职预览。

首页主要用于快速进入服务分类，并让用户看到平台最近的活跃内容。

### 4.2 快递代取

快递代取包含：

- 快递任务列表。
- 快递任务详情。
- 发布快递代取任务。
- 接单。
- 接单后进入订单和私聊。

发布字段可包括快递地点、取件码备注、送达地点、报酬、期望完成时间和补充说明。取件码等敏感信息建议在私聊中发送，不直接显示在公开详情页。

### 4.3 代办

代办包含：

- 代办列表。
- 代办详情。
- 发布代办。
- 接单。

适合打印、送资料、买东西、占座、排队等场景。发布字段包括任务描述、地点、报酬、截止时间和注意事项。

### 4.4 课程互助

课程互助包含：

- 课程互助列表。
- 课程互助详情。
- 发布课程互助。
- 接单。

适合课程答疑、复习资料、学习搭子、作业思路交流等场景。发布字段包括课程名称、互助类型、时间、地点或线上方式、报酬和说明。

### 4.5 二手交易

二手交易包含：

- 商品列表。
- 商品详情。
- 发布商品。
- 下单。
- 私聊沟通。

下单不代表已付款，只表示买卖双方建立联系。商品详情页需要提示建议当面验货、确认物品状态后再付款。

### 4.6 兼职

兼职包含：

- 兼职列表。
- 兼职详情。
- 发布兼职。
- 报名/联系。

兼职字段包括岗位名称、薪资、工作时间、工作地点、招聘人数、岗位要求、结算方式和补充说明。报名后生成订单和会话，但不代表最终录用。

### 4.7 私聊

私聊包含：

- 会话列表。
- 聊天页面。
- 文本消息发送。
- 消息轮询刷新。
- 一键交换微信。

聊天采用轮询刷新方案。用户发送消息后立即写入云数据库并显示，聊天页每隔几秒拉取新消息，达到接近实时聊天的演示效果。

### 4.8 一键交换微信

微信交换采用双方同意机制：

1. 用户在个人资料中填写微信号，并设置是否允许交换。
2. 聊天页显示“交换微信”按钮。
3. A 发起交换请求后，B 收到请求消息。
4. B 同意后，双方聊天页都显示对方微信号。
5. B 拒绝后，聊天中显示拒绝结果，不展示微信号。

微信号不在任务详情页直接公开，避免隐私泄露。

### 4.9 评价与信誉

订单完成后双方可以互评。评价影响信誉分和段位。

评价类型：

- 好评。
- 中评。
- 差评。

信誉分规则：

| 行为 | 分数变化 |
| --- | ---: |
| 完成一次订单 | 双方各 +20 |
| 获得好评 | 被评价方额外 +10 |
| 获得中评 | 不额外加分 |
| 获得差评 | -10 |
| 投诉成立 | 管理员可扣分或禁用账号 |

段位规则：

| 段位 | 信誉分范围 |
| --- | ---: |
| 青铜 | 0 - 99 |
| 白银 | 100 - 199 |
| 黄金 | 200 - 399 |
| 铂金 | 400 - 699 |
| 钻石 | 700 - 999 |
| 星耀 | 1000 - 1499 |
| 王者 | 1500+ |

月度掉段规则：

- 每月 1 日系统检查用户上月完成订单数。
- 如果上月没有完成订单，则自动下降 1 个段位。
- 每月最多下降 1 个段位。
- 青铜不继续下降。
- 管理员账号不参与掉段。
- 掉段后信誉分调整到对应段位区间内，例如黄金降到白银后可调整为 199 分。

第一版建议在用户登录时检查自己是否需要掉段，同时在管理员页面提供“执行月度段位检查”按钮，方便演示。

### 4.10 消息通知

通知包含：

- 系统通知。
- 订单状态通知。
- 聊天提醒。
- 评价提醒。
- 投诉处理结果通知。

通知可以先做站内消息，不接入真实微信订阅消息。

### 4.11 个人中心

个人中心包含：

- 头像、昵称、学校、学院。
- 微信号设置。
- 是否允许交换微信。
- 当前信誉分。
- 当前段位。
- 段位升级进度条。
- 我的发布。
- 我的接单。
- 我的下单。
- 我的报名。
- 我的评价。
- 系统通知。
- 管理员入口。

### 4.12 小程序内管理员页面

管理员入口放在个人中心中，仅管理员可见。管理员页面包含：

- 用户管理：查看用户、信誉分、段位、禁用或恢复账号。
- 内容管理：管理快递、代办、课程、二手和兼职发布内容。
- 订单管理：查看订单状态，处理异常订单。
- 评价管理：查看评价，隐藏违规评价。
- 通知管理：发布系统通知。
- 投诉管理：查看投诉，标记处理结果。
- 月度段位检查：手动触发段位检查，用于演示。

第一版以查看和状态处理为主，不做复杂审核流。

## 6. 核心业务流程

### 6.1 任务型服务流程

适用于快递代取、代办、课程互助：

1. 发布者发布任务，内容状态为待接单。
2. 其他学生点击接单。
3. 系统创建订单和私聊会话。
4. 内容状态变为已接单，订单状态变为进行中。
5. 双方通过私聊协商细节。
6. 任务完成后，发布者点击确认完成。
7. 订单进入待评价。
8. 双方评价。
9. 系统更新信誉分和段位。
10. 订单变为已完成。

### 6.2 二手交易流程

1. 卖家发布二手商品。
2. 买家点击下单。
3. 系统创建订单和私聊会话。
4. 双方私聊沟通交易地点、价格、验货方式。
5. 线下验货和结算。
6. 卖家确认完成。
7. 双方评价并更新信誉分。

### 6.3 兼职报名流程

1. 发布者发布兼职信息。
2. 学生点击报名。
3. 系统创建订单和私聊会话。
4. 双方沟通时间、地点、要求和结算方式。
5. 发布者确认完成。
6. 双方评价并更新信誉分。

## 7. 状态规则

内容状态：

| 状态 | 含义 |
| --- | --- |
| `open` | 待接单，其他用户可操作 |
| `locked` | 已接单/下单/报名，暂时锁定 |
| `completed` | 已完成 |
| `cancelled` | 已取消 |
| `disputed` | 纠纷中 |

订单状态：

| 状态 | 含义 |
| --- | --- |
| `accepted` | 已创建订单 |
| `in_progress` | 进行中，双方正在沟通或执行 |
| `pending_review` | 发布者已确认完成，等待双方评价 |
| `completed` | 已完成，信誉分已结算 |
| `cancelled` | 已取消 |
| `disputed` | 纠纷中 |

关键规则：

- 接单者不能单方面完成订单。
- 发布者确认完成后才能进入评价。
- 用户投诉后订单进入纠纷中。
- 管理员可以处理纠纷、隐藏评价、禁用账号或调整状态。

## 8. 防诈骗与纠纷处理

由于第一版不接真实支付，平台不做资金托管，不承诺赔付。防诈骗机制以提醒、留痕、信誉、投诉和管理处理为主。

防骗规则：

| 场景 | 处理方式 |
| --- | --- |
| 提前转账风险 | 任务详情、二手详情和聊天页提示不要提前支付大额费用 |
| 二手虚假商品 | 商品详情提示当面验货，支持举报和管理员下架 |
| 接单者谎称完成 | 只有发布者可以确认完成 |
| 发布者恶意不确认 | 接单者可投诉，管理员查看聊天记录处理 |
| 私下诈骗 | 聊天敏感词触发风险提示 |
| 微信号泄露 | 必须双方同意后才显示微信号 |
| 恶意评价 | 支持评价投诉，管理员可隐藏违规评价 |
| 账号风险 | 管理员可禁用用户，低信誉用户显著提醒 |

风险提示可以出现在：

- 任务详情页。
- 商品详情页。
- 兼职详情页。
- 聊天页。
- 微信交换成功提示中。

聊天敏感词第一版可先在前端识别，例如：

- 先转账。
- 押金。
- 保证金。
- 私下交易。
- 不走平台。
- 加微信付款。

触发后展示风险提醒，不阻止用户继续聊天。

## 10. 云函数设计

建议云函数：

| 云函数 | 作用 |
| --- | --- |
| `login` | 获取 openid，初始化用户 |
| `createPost` | 发布五类内容 |
| `acceptOrder` | 接单/下单/报名，创建订单和会话 |
| `sendMessage` | 发送聊天消息 |
| `confirmComplete` | 发布者确认完成，订单进入待评价 |
| `submitReview` | 评价并更新信誉分和段位 |
| `requestWechatExchange` | 发起微信交换请求 |
| `respondWechatExchange` | 同意或拒绝微信交换 |
| `createComplaint` | 创建投诉 |
| `adminUpdateStatus` | 管理员处理内容、订单、评价和投诉 |
| `monthlyRankDecay` | 月度段位检查，未完成订单的用户自动掉段 |

关键逻辑应放在云函数中，避免用户直接在前端修改订单状态、信誉分或段位。

## 13. 第一版边界

第一版明确不做：

- 不接入真实微信支付。
- 不做资金托管。
- 不承诺赔付。
- 不做独立 Web 管理后台。
- 不做复杂推荐算法。
- 不做真实微信订阅消息。

第一版重点完成：

- 五类服务发布和浏览。
- 接单/下单/报名。
- 私聊协商。
- 发布者确认完成。
- 双方评价。
- 信誉分和段位。
- 月度掉段。
- 投诉和管理员处理。
