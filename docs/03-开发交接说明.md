## 四、怎么让队友一起开发

### 现状：仓库已经建好，不用再折腾

代码已经在 GitHub 上了：

```
https://github.com/Dying-wq/tonglu
```

- 分支：`main`
- 基线提交：`19c5278`（197 个文件）
- 可见性：公开（队友可以直接 clone，无需邀请也能读）

**但「能读」不等于「能推」。** 要改代码并推上来，必须由管理员授权，见下面 4.1。

### 为什么不用压缩包

压缩包在 2 人以上协作时必然出问题，原因很具体：

| 问题 | 后果 |
|---|---|
| 无法合并修改 | A 改了 `home.js`，B 也改了，只能二选一 |
| 版本无法追溯 | 出问题时不知道是谁、哪次改动引入的 |
| 配置污染 | `project.private.config.json` 里存的是**本机绝对路径**，传给对方会失效 |
| 体积浪费 | 若含 `node_modules`，压缩包会到几百 MB |

### 4.1 管理员要做的事：两处授权，缺一不可

很多人只做了第一处，结果队友「代码能拉下来，但云开发用不了」。

#### ① GitHub 授权（管代码）

```
https://github.com/Dying-wq/tonglu/settings/access
```

→ 点 **Add people** → 输入队友的 **GitHub 用户名**（是 `@` 后面那个，不是昵称）→ 权限选 `Write` → 发送邀请。

队友在邮箱里点接受后，才有推送权限。

> 队友没有 GitHub 账号的话要先注册。**提前一周让他们注册**，不要等到开会当天。

#### ② 微信公众平台授权（管云开发）

```
https://mp.weixin.qq.com/ → 管理 → 成员管理 → 项目成员 → 添加
```

输入队友**微信号**，角色选「开发者」，队友在微信里接受。

**不做这一步的后果**：队友打开项目后，云开发图标是灰的 / 点开是空的 / 云函数列表为空 / 数据库连不上。他会以为代码坏了，实际是没权限。

### 4.2 队友每天的操作流程

只需要记住四个动作：

```bash
# 1. 开工前：拉取最新代码（必做，否则会冲突）
git pull

# 2. 改代码……（在开发者工具里正常改）

# 3. 收工前：看看自己改了哪些文件
git status

# 4. 提交并推送
git add -A
git commit -m "feat: 完成了xxx功能"
git push
```

**用微信开发者工具的图形界面也能做同样的事**：

| 动作 | 界面位置 |
|---|---|
| 拉取 | 左侧「版本管理」→ 顶部「拉取」按钮（↓ 图标） |
| 提交 | 左侧「版本管理」→ 填 Message → 点绿色 `Commit` |
| 推送 | 提交后点「推送」按钮（↑ 图标） |

**图形界面和命令行可以混用**，它们操作的是同一个 `.git` 目录，不会冲突。哪个顺手用哪个。

### 4.3 提交信息怎么写

不用学复杂的规范，但**必须让人一眼看懂改了什么**。三种前缀够用了：

| 前缀 | 什么时候用 | 例子 |
|---|---|---|
| `feat:` | 加了新功能 | `feat: 首页增加按时间排序` |
| `fix:` | 修了 bug | `fix: 修复解绑后仍显示帖子` |
| `docs:` | 只改文档 | `docs: 补充队友上手指南` |

反面例子：`update`、`修改`、`1`、`aaa` —— 这种提交信息三个月后自己都看不懂。

### 4.4 遇到冲突怎么办

**冲突只会发生在两个人改了同一个文件的同一片区域。**

现象：`git pull` 时报 `CONFLICT (content): Merge conflict in xxx.js`。

处理步骤：

1. 打开冲突文件，会看到这样的标记：

```js
<<<<<<< HEAD
你的代码
=======
队友的代码
>>>>>>> origin/main
```

2. 手动决定保留哪部分（或者两段都留），**删掉 `<<<<<<<`、`=======`、`>>>>>>>` 这三行标记**；
3. 保存，然后：

```bash
git add -A
git commit -m "fix: 解决 xxx.js 冲突"
git push
```

**预防冲突比解决冲突重要**：按文件分工，不要让两个人同时改同一个文件，见 4.5。

### 4.5 三条协作纪律（比工具更重要）

**1. 开工先拉取，收工先推送。** 每天两次，雷打不动。

**2. 按文件分工，不要按功能分工。**

例如：
- A 负责 `pages\home\`、`pages\publish\`
- B 负责 `pages\message\`、`pages\service-detail\`
- C 负责 `cloudfunctions\` 下新增的函数

同一个文件两人同时改，一定会冲突。**分工的边界要落到「谁负责哪些文件」。**

**3. 云函数改动后必须重新部署，否则云端跑的还是旧代码。**

这一点最容易让队友困惑：「我明明改了，怎么没效果？」

正确操作：右键该云函数 → 「创建并部署：云端安装依赖」。**每次改完都要重新部署，且部署是单人操作，不要两个人同时部署同一个函数。**

### 4.6 关于网络：GitHub 需要代理

**这是本次搭建踩过的坑，队友一定会再遇到。**

实测结果（2026-10-17）：

| 目标 | 直连 | 走代理 |
|---|---|---|
| `github.com` | ❌ 超时 | ✅ 正常 |
| `api.github.com` | ✅ 正常 | ✅ 正常 |

**结论：Git 必须单独配置代理，它不会自动读取代理软件的设置。**

代理软件端口以你自己电脑为准（本次是 `7897`）。确认端口的方法：打开代理软件看「HTTP 代理端口」或「混合端口」。

配置命令（**只需要执行一次，永久生效**）：

```bash
git config --global http.proxy http://127.0.0.1:7897
git config --global https.proxy http://127.0.0.1:7897
```

验证：

```bash
git ls-remote https://github.com/Dying-wq/tonglu.git
```

能返回一串 40 位哈希值就说明通了。

**注意**：配置后 Git 依赖代理软件运行。如果哪天关了代理，Git 会连不上，报 `Failed to connect to 127.0.0.1 port 7897`。这时要么打开代理软件，要么临时取消：

```bash
git config --global --unset http.proxy
git config --global --unset https.proxy
```

### 4.7 关于认证：用令牌，不用密码

GitHub 从 2021 年起**不再支持用账号密码推送**，必须用 Personal Access Token（PAT）。

管理员第一次推送时已经配置好了，令牌保存在：

```
C:\Users\<用户名>\.git-credentials
```

**队友第一次 `git push` 时会被要求输入账号密码**：

- Username：GitHub 用户名（`Dying-wq` 这样的）
- Password：**粘贴 PAT**（不是登录密码！）

如果队友还没配置过，让他自己生成一个令牌：

```
https://github.com/settings/tokens/new
```

⚠️ **关键：必须勾选 `repo` 权限**，否则推送会报 `403 Permission denied`。

生成后复制 `ghp_` 开头的那串，在 push 时当密码粘贴。

> **踩坑提醒**：这一步本次踩过。第一次生成的令牌没勾 `repo`，push 直接 403，且报错信息只说「denied」，不说原因，很容易误以为是仓库地址错了。诊断方法见第五节第 16 条。

### 4.8 如果队友完全不会 Git

过渡方案：压缩包传递，但必须遵守两条：

1. **排除 `project.private.config.json` 和 `node_modules`**，否则对方打开会出配置问题；
2. **约定同一时间只有一个人在改**，改完传给下一个。

这只是权宜之计，最多撑两周。三个人以上协作，必须上 Git。

## 五、今天遇到的问题（队友大概率会重复踩）

以下每一条都是今天真实发生过的，按发生顺序排列。

### 1. 代码在 zip 里没解压，报「找不到 app.json」

**现象**：`Error: app.json: 在项目根目录未找到 app.json`

**原因**：开发者工具只认文件夹，不会自动解压 zip。打开的是压缩包所在的那层目录，里面只有文档没有代码。

**解决**：解压后导入代码所在的那一层目录。

### 2. 云开发按钮是灰的，点不了

**现象**：「云开发」按钮灰色不可点击，「上传」按钮也是灰的。

**原因**：用了**小程序测试号**。测试号 AppID 格式和正式号完全一样（都是 `wx` 开头 18 位），肉眼无法区分。

**判断方法**：开发者工具本地记录里 `appName` 字段会写明「xxx的小程序测试号」。

**解决**：注册正式小程序（个人主体，免费），换 AppID，并用该小程序的管理员微信重新登录开发者工具。

### 3. 开通云开发只有付费选项，没有免费

**原因**：2026 年起免费环境不再由开通页直接提供，改为通过「**AI 小程序成长计划**」发放。

**解决**：微信公众平台 → 左侧「行业能力」→「AI 小程序成长计划」→ 参与计划。报名后免费获得 6 个月个人版环境。

**前置条件**：小程序类目必须是文娱、工具、社交、深度合成、资讯这类虚拟服务，线下实体类目看不到入口。

⚠️ 开通页默认选中「个人版（连续订阅）」，会自动续费。若必须付费，改选「单月」。

### 4. 云函数目录没有云图标、右键没有部署选项

**原因**：工具没重新加载项目结构缓存。

**解决**：菜单「项目」→「关闭当前项目」→ 重新打开。仍不行就完全退出工具再启动。

### 5. 部署报「请在编辑器云函数根目录选择一个云环境」

**原因**：`cloudfunctions` 根目录没绑定环境。

**解决**：**右键 `cloudfunctions` 根目录本身**（不是 `login` 这类子文件夹）→ 选「选择云环境」→ 选 `tonglu-dev`。

判断成功的标志：目录名后缀从「(未选择环境)」变成「(tonglu-dev)」。

### 6. 集合名写成 `user`，登录一直失败

**原因**：代码里是 `db.collection('users')`，复数。

**解决**：集合名严格全小写，`users` 不是 `user`。

### 7. 编译后「我的」页面登录不触发，云函数日志一条记录都没有

**原因**：`login` 写在 `pages/profile/profile.js` 的 `onLoad` 里。tabBar 页面第二次进入只触发 `onShow`，不再触发 `onLoad`。编译会重启小程序回到首页，「我的」页面被卸载。

**正确顺序**：**先编译 → 再点「我的」**。

### 8. 数据库里有记录，控制台却看不到

**原因**：控制台默认停在「**索引管理**」标签。

**解决**：切到「**记录列表**」。

### 9. 绑定新车次后，首页冒出一堆没见过的帖子

**原因**：代码里有两处「假数据兜底」：
- `home.js` 判断 `nextPosts.length ? nextPosts : posts`，空列表被当成加载失败；
- `cloud-api.js` 的 catch 分支在查询异常时也返回 mock 数据。

而 `mock-data.js` 里 8 条假帖子的车次**全是 K1234**，所以绑 K1234 时看起来特别「真」。

**已修复**：两处都改为云开发就绪时不回退假数据。

**通用原则**：**判断功能是否正常，只看数据库有没有记录，不看界面有没有内容。**

### 10. 解绑后再绑定报错 `Cannot create field 'xxx' in element {trainBinding: null}`

**原因**：微信云数据库的 `update` 对嵌套对象是**合并**语义，会拆成 `trainBinding.trainNo` 逐字段写入。原值被设成 `null` 后，往 `null` 上挂子字段就会失败。

**已修复**：`bindTrain` 改用 `_.set(binding)` 强制整体替换，`unbindTrain` 改用 `_.remove()` 删除字段。

### 11. 解绑车次后能看到全平台帖子

**原因**：`getPosts` 在未绑定时不加车次过滤条件。

**已修复**：未绑定直接返回空列表，页面显示「请先绑定车次查看同车信息」。

### 12. 所有云调用突然失败，报 `no baseresponse`

**现象**：数据库查询和云函数调用同时报 `Error: no baseresponse`。

**关键判断**：**所有云调用同时失败 = 网络或环境问题**，不可能是某个功能代码写错。

**原因**：Windows 系统代理指向了一个已经关闭的端口（代理软件换端口后系统设置没更新）。开发者工具走系统代理，请求发到无人监听的端口。

**解决**：开发者工具 → 设置 → 代理设置 → 选「**不使用任何代理**」。云开发是国内服务，不需要代理。

### 13. 改了云函数代码，运行没变化

**原因**：云函数改的是本地文件，云端跑的还是旧版本。

**解决**：右键该函数 → 「创建并部署：云端安装依赖」。**每次改完都要重新部署。**

### 14. 写入成功、数据库有记录，但页面列表永远为空，且不报错

**原因**：集合权限设得太严。前端直接查数据库的集合如果设成「仅创建者可读写」，读不到别人的数据。

**解决**：见第七节权限表。`posts`、`orders` 必须设「所有用户可读」。

### 15. 浏览器能打开 GitHub，但 Git 推不上去

**现象**：网页能正常访问 `github.com`，但 `git clone` / `git push` 卡住不动，或报 `Failed to connect to github.com port 443`。

**原因**：**Git 是独立程序，不会自动使用代理软件的设置。** 浏览器走代理所以能上网，Git 走直连所以被墙。

这不是「你没代理」，而是「Git 不知道要用代理」。

**判断方法**：

```bash
# 直连测试（大概率超时）
curl -o /dev/null -w "%{http_code}\n" --max-time 10 https://github.com
```

返回 `000` 就是不通。

**解决**：给 Git 单独配代理，端口填你代理软件里的端口：

```bash
git config --global http.proxy http://127.0.0.1:7897
git config --global https.proxy http://127.0.0.1:7897
```

配置后验证：

```bash
git ls-remote https://github.com/Dying-wq/tonglu.git
```

返回 40 位哈希值即成功。

**反向坑**：配置代理后，**关掉代理软件 Git 就断了**，报 `Failed to connect to 127.0.0.1 port 7897`。这时开代理，或临时取消配置（见 4.6）。

### 16. 推送报 403 Permission denied，但账号和仓库都是对的

**现象**：

```
remote: Permission to Dying-wq/tonglu.git denied to Dying-wq.
fatal: unable to access '...': The requested URL returned error: 403
```

注意这句话的意思：**GitHub 已经认出了你是谁**（`denied to Dying-wq`），但拒绝你写入。

**原因**：Personal Access Token **没有勾选 `repo` 权限**。空的令牌只能读公开信息，一写就 403。

**诊断方法**（把 `你的令牌` 换成实际值）：

```bash
curl -s -D - -o /dev/null -H "Authorization: token 你的令牌" https://api.github.com/user | findstr /i "x-oauth-scopes"
```

- 返回 `X-OAuth-Scopes: repo` → 权限正常
- 返回 `X-OAuth-Scopes:`（空的）→ **就是这个原因**

**解决**：删掉旧令牌，重新生成：

1. `https://github.com/settings/tokens` → 找到旧令牌 → Delete；
2. `https://github.com/settings/tokens/new` → 填 Note、选 Expiration；
3. **往下滚动到「Select scopes」区域，勾选第一个 `repo`**（它下面 5 个子项会自动全选，正常）；
4. 滚到最底部 → Generate token → 复制 `ghp_` 开头的串。

> **为什么容易漏**：`repo` 复选框在页面中间，而「Generate token」按钮在最底部。直接滚到底点按钮就会生成一个空权限的令牌，报错还不说明原因。

### 17. 推送成功后，开发者工具的「Changes」里还显示一堆文件

**原因**：面板没有刷新，或者显示的是提交前的缓存状态。

**判断依据**：以命令行为准。

```bash
git status
```

输出 `nothing to commit, working tree clean` 就是真的干净了。

**解决**：点「源码管理」标题旁的刷新图标，或关掉面板重新打开。

⚠️ **不要在这种情况下再点一次 `Commit`**，会产生空提交。

## 七、数据库权限速查

| 集合 | 权限 | 原因 |
|---|---|---|
| `users` | 仅创建者可读写 | 前端不直查，全走云函数 |
| `posts` | **所有用户可读** | 首页、详情、我的发布均前端直查 |
| `orders` | **所有用户可读** | 订单详情前端直查 |
| `conversations` | 仅创建者可读写 | 兜底直查无 openid 过滤，开放读权限会泄露全平台会话 |
| `messages` | 仅创建者可读写 | 私信只能通过云函数鉴权后返回 |

**通用规则**：写入全部走云函数（管理员权限，不受集合权限限制）；只有**前端直查**的集合才需要开放读权限。

**设错的症状**：写入成功、数据库有记录，但页面永远空白，**且不报错**。
