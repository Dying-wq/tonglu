## 三、队友第一次接入（必做五步）

### 第 1 步：获取代码

见第四节「协作方式」。**不要直接用微信传压缩包**，原因在第四节说明。

### 第 2 步：确认 AppID 权限

**这一步最容易漏，漏了就无法真机预览。**

小程序的管理员需要把你加为开发者：

1. 管理员登录 `https://mp.weixin.qq.com/`；
2. 左侧「管理」→「成员管理」→「项目成员」→ 添加成员；
3. 输入你的微信号，角色选「开发者」；
4. 你在微信里接受邀请。

### 第 3 步：打开项目

微信开发者工具 → 导入项目 → 选择 **`campus-mutual-aid-miniprogram-main` 这一层**。

⚠️ 不要选外层 `D:\同路微光`，那一层没有 `app.json`，会报「在项目根目录未找到 app.json」。

### 第 4 步：确认云环境配置

打开 `miniprogram\config.js`，确认第 1 行：

```js
const CLOUD_ENV_ID = 'tonglu-dev-d1g7ykjzt01f2dcf7';
```

### 第 5 步：绑定云函数环境

**右键 `cloudfunctions` 文件夹本身**（不是里面的子文件夹）→ 选「选择云环境」→ 选 `tonglu-dev`。

不绑定会报：`请在编辑器云函数根目录（cloudfunctionRoot）选择一个云环境`。

### 验证是否接入成功

编译 → 点底部「我的」→ 云开发控制台 → 数据库 → `users` → **「记录列表」**，应出现你的记录。

> 注意：控制台默认停在「索引管理」标签，那里看不到数据，必须切到「记录列表」。

## 四、怎么让队友一起开发

### 结论：用 Git，不要用压缩包

压缩包在 2 人以上协作时必然出问题，原因很具体：

| 问题 | 后果 |
|---|---|
| 无法合并修改 | A 改了 `home.js`，B 也改了，只能二选一 |
| 版本无法追溯 | 出问题时不知道是谁、哪次改动引入的 |
| 配置污染 | `project.private.config.json` 里存的是**本机绝对路径**，传给对方会失效 |
| 体积浪费 | 若含 `node_modules`，压缩包会到几百 MB |

### 推荐方案：微信开发者工具自带的版本管理

不需要命令行，界面上就能完成。

**管理员（你）操作一次：**

1. 在 Gitee（国内速度快）或 GitHub 新建一个**私有**仓库；
2. 开发者工具左侧点「**版本管理**」图标（分支形状）；
3. 点「初始化 Git 仓库」→ 填写用户名和邮箱；
4. 点「远程」→「添加远程仓库」→ 粘贴仓库地址；
5. 提交所有文件 → 推送。

**队友操作一次：**

1. 开发者工具 → 导入项目 → 选择「**从 Git 仓库导入**」→ 粘贴仓库地址；
2. 之后每次开工点「**拉取**」，收工点「**提交 + 推送**」。

### 三条协作纪律（比工具更重要）

**1. 开工先拉取，收工先推送。** 每天两次，雷打不动。

**2. 按文件分工，不要按功能分工。**
例如：
- A 负责 `pages\home\`、`pages\publish\`
- B 负责 `pages\message\`、`pages\service-detail\`
- C 负责 `cloudfunctions\` 下新增的函数

同一个文件两人同时改，一定会冲突。**分工的边界要落到「谁负责哪些文件」。**

**3. 云函数改动后必须重新部署，否则云端跑的还是旧代码。**
这一点最容易让队友困惑：「我明明改了，怎么没效果？」

### 如果队友完全不会 Git

过渡方案：压缩包传递，但必须遵守两条：

1. **排除 `project.private.config.json` 和 `node_modules`**，否则对方打开会出配置问题；
2. **约定同一时间只有一个人在改**，改完传给下一个。

这只是权宜之计，最多撑两周。三个人以上协作，必须上 Git。

## 五、今天遇到的问题（队友大概率会重复踩）

以下每一条都是今天真实发生过的，按发生顺序排列。

### 1. 代码在 zip 里没解压，报「找不到 app.json」

**现象**：`Error: app.json: 在项目根目录未找到 app.json`

**原因**：开发者工具只认文件夹，不会自动解压 zip。打开的是压缩包所在的那层目录，里面只有文档没有代码。

**解决**：解压后导入代码所在的那一层目录。

### 2. 云开发按钮是灰的，点不了

**现象**：「云开发」按钮灰色不可点击，「上传」按钮也是灰的。

**原因**：用了**小程序测试号**。测试号 AppID 格式和正式号完全一样（都是 `wx` 开头 18 位），肉眼无法区分。

**判断方法**：开发者工具本地记录里 `appName` 字段会写明「xxx的小程序测试号」。

**解决**：注册正式小程序（个人主体，免费），换 AppID，并用该小程序的管理员微信重新登录开发者工具。

### 3. 开通云开发只有付费选项，没有免费

**原因**：2026 年起免费环境不再由开通页直接提供，改为通过「**AI 小程序成长计划**」发放。

**解决**：微信公众平台 → 左侧「行业能力」→「AI 小程序成长计划」→ 参与计划。报名后免费获得 6 个月个人版环境。

**前置条件**：小程序类目必须是文娱、工具、社交、深度合成、资讯这类虚拟服务，线下实体类目看不到入口。

⚠️ 开通页默认选中「个人版（连续订阅）」，会自动续费。若必须付费，改选「单月」。

### 4. 云函数目录没有云图标、右键没有部署选项

**原因**：工具没重新加载项目结构缓存。

**解决**：菜单「项目」→「关闭当前项目」→ 重新打开。仍不行就完全退出工具再启动。

### 5. 部署报「请在编辑器云函数根目录选择一个云环境」

**原因**：`cloudfunctions` 根目录没绑定环境。

**解决**：**右键 `cloudfunctions` 根目录本身**（不是 `login` 这类子文件夹）→ 选「选择云环境」→ 选 `tonglu-dev`。

判断成功的标志：目录名后缀从「(未选择环境)」变成「(tonglu-dev)」。

### 6. 集合名写成 `user`，登录一直失败

**原因**：代码里是 `db.collection('users')`，复数。

**解决**：集合名严格全小写，`users` 不是 `user`。

### 7. 编译后「我的」页面登录不触发，云函数日志一条记录都没有

**原因**：`login` 写在 `pages/profile/profile.js` 的 `onLoad` 里。tabBar 页面第二次进入只触发 `onShow`，不再触发 `onLoad`。编译会重启小程序回到首页，「我的」页面被卸载。

**正确顺序**：**先编译 → 再点「我的」**。

### 8. 数据库里有记录，控制台却看不到

**原因**：控制台默认停在「**索引管理**」标签。

**解决**：切到「**记录列表**」。

### 9. 绑定新车次后，首页冒出一堆没见过的帖子

**原因**：代码里有两处「假数据兜底」：
- `home.js` 判断 `nextPosts.length ? nextPosts : posts`，空列表被当成加载失败；
- `cloud-api.js` 的 catch 分支在查询异常时也返回 mock 数据。

而 `mock-data.js` 里 8 条假帖子的车次**全是 K1234**，所以绑 K1234 时看起来特别「真」。

**已修复**：两处都改为云开发就绪时不回退假数据。

**通用原则**：**判断功能是否正常，只看数据库有没有记录，不看界面有没有内容。**

### 10. 解绑后再绑定报错 `Cannot create field 'xxx' in element {trainBinding: null}`

**原因**：微信云数据库的 `update` 对嵌套对象是**合并**语义，会拆成 `trainBinding.trainNo` 逐字段写入。原值被设成 `null` 后，往 `null` 上挂子字段就会失败。

**已修复**：`bindTrain` 改用 `_.set(binding)` 强制整体替换，`unbindTrain` 改用 `_.remove()` 删除字段。

### 11. 解绑车次后能看到全平台帖子

**原因**：`getPosts` 在未绑定时不加车次过滤条件。

**已修复**：未绑定直接返回空列表，页面显示「请先绑定车次查看同车信息」。

### 12. 所有云调用突然失败，报 `no baseresponse`

**现象**：数据库查询和云函数调用同时报 `Error: no baseresponse`。

**关键判断**：**所有云调用同时失败 = 网络或环境问题**，不可能是某个功能代码写错。

**原因**：Windows 系统代理指向了一个已经关闭的端口（代理软件换端口后系统设置没更新）。开发者工具走系统代理，请求发到无人监听的端口。

**解决**：开发者工具 → 设置 → 代理设置 → 选「**不使用任何代理**」。云开发是国内服务，不需要代理。

### 13. 改了云函数代码，运行没变化

**原因**：云函数改的是本地文件，云端跑的还是旧版本。

**解决**：右键该函数 → 「创建并部署：云端安装依赖」。**每次改完都要重新部署。**

### 14. 写入成功、数据库有记录，但页面列表永远为空，且不报错

**原因**：集合权限设得太严。前端直接查数据库的集合如果设成「仅创建者可读写」，读不到别人的数据。

**解决**：见第七节权限表。`posts`、`orders` 必须设「所有用户可读」。

## 六、已知缺陷（未修复，队友接手需了解）

### 🔴 图片上传功能实际未实现

`miniprogram\pages\publish\publish.js` 的 `chooseImages()` 只取了 `tempFilePath`（本地临时路径），**没有调用 `wx.cloud.uploadFile`**。

后果：图片只有发布者自己能看到，存进数据库的是一堆无效本地路径，其他用户完全看不到。

README 写着「支持图片上传」，但代码没实现。**这是必须补的功能。**

### 🔴 订单与消息链路完全未验证

`orders`、`conversations`、`messages` 三个集合已建，6 个相关云函数已部署，但**从未实际跑通过一次**。

私信测试**必须用两个微信号**（一个发、一个收），单人无法完成。排期时要单独预留时间。

### 🟡 车次绑定固定 3 小时后过期

`pages\train-binding\train-binding.js` 第 65 行：

```js
const arrivalTs = Date.now() + 3 * 60 * 60 * 1000;
```

不管实际车程多长，固定 3 小时失效。应按车次真实到达时间计算。

### 🟡 修改绑定不保留历史

`bindTrain` 用新对象整体覆盖 `trainBinding`，旧车次、绑定时间全部丢失。后续若要做「行程记录」或「同车互助统计」，当前结构无法支撑。

### 🟡 「我的参与」仍是假数据

`profile.js` 的 `buildPanels` 里 `orders: [demoOrder]` 仍是 `mock-data.js` 的演示数据。`orders` 集合的真实数据尚未接入。

### 🟢 4 个页面目录是废弃的

`miniprogram\pages\` 下有 21 个目录，`app.json` 只注册了 18 个。以下 4 个**不会生效**：

```text
pages\chat\        ← 废弃
pages\messages\    ← 废弃（复数）
pages\hot\         ← 废弃
pages\map\         ← 废弃
```

真正的聊天页是 **`pages\message\chat`（单数）**。

**判断方法**：只有 `app.json` 的 `pages` 数组里列出的页面才会加载。改错文件会出现「改了完全没反应」。

## 七、数据库权限速查

| 集合 | 权限 | 原因 |
|---|---|---|
| `users` | 仅创建者可读写 | 前端不直查，全走云函数 |
| `posts` | **所有用户可读** | 首页、详情、我的发布均前端直查 |
| `orders` | **所有用户可读** | 订单详情前端直查 |
| `conversations` | 仅创建者可读写 | 兜底直查无 openid 过滤，开放读权限会泄露全平台会话 |
| `messages` | 仅创建者可读写 | 私信只能通过云函数鉴权后返回 |

**通用规则**：写入全部走云函数（管理员权限，不受集合权限限制）；只有**前端直查**的集合才需要开放读权限。

**设错的症状**：写入成功、数据库有记录，但页面永远空白，**且不报错**。
