## 零、代码审计结论（先看这个）

第四批交接文档里留下的两个疑问，接手前已逐一核查：

**1. 取消拉黑按钮 —— 渲染链路完整，但「推不出对方是谁」时会失败（已修复）。**
整条链路：聊天页按钮渲染（`chat.wxml`）→ 服务端拉黑状态计算（`getMessageList`）→
取消拉黑（`unblockUser`）→ 会话列表保留已拉黑会话并打标签（`getConversationList`）。

2026-11-07 实测发现一个真实缺口：**单账号自测时，会话是「自己跟自己聊」**
（对自己的帖子点「联系发布人」，`createOrGetConversation` 用
`new Set([publisherOpenid, openid])` 建会话，两个值相同 → `participantIds` 只有一个人）。
此时页面上显示的是默认的「同车旅客 / 旅」头像，`getMessageList` 返回 `peerOpenid: ''`，
`unblockUser` 推不出对方，就弹出「取消拉黑未成功 / 无法确定要取消拉黑的用户。」。

本次已加固：多来源推断对方 openid、单账号会话自动恢复脏状态并明确提示、
`blockUser` 拒绝写入空对象的垃圾记录、云函数返回 `version` 便于确认部署。
**改的是云函数，必须重新上传部署才生效**（见第五节、第十一节）。

**2. 私信时间显示 —— 已修复一处会导致「时间不对」的真实缺陷。**
`formatTime` 在收到日期对象/序列化对象时会算出 NaN，界面显示「NaN 天前」。
已新增统一解析函数 `parseDateValue` 修复（详见第九节）。

**3. 双账号完整链路 —— 代码侧已补齐 4 个挡路问题（2026-11-08）。**
审计发现：发布失败仍提示「同车旅客可见」；「我来帮」失败仍跳到 `orderId=` 的空订单页；
`globalData.openid` 只在聊天页/资料页登录，发布者从首页直接进订单详情时看不到
「接受接单 / 确认完成」；消息页没有订单确认入口。另外详情页/订单详情还残留
`mock-data` 假数据回退。这 5 处已修，并接入帖子评论（详见第九节）。

**4. 帖子评论 —— 已接入，沿用当前云环境。**
只在现有环境里新增一个 `comments` 集合和 `comments` 云函数，
前端不直查数据库；没有另建环境、没有第二套数据源。

## 七、验证「取消拉黑」（上一批遗留项，最先做这个）

### 方式 A：双账号真实路径（推荐，最可信）

1. 账号 A、B 都绑定同一车次；
2. A 发帖 → B 看到帖子 → B 私信 A（建立会话）；
3. A 进「消息」页 → 点进会话 → 右上工具条点「拉黑」；
4. **退出小程序 → 重新进入**；
5. 消息列表里会话还在（带「已拉黑」标签）→ 点进聊天页；
6. 顶部出现「已拉黑」标签 + 底部出现**「取消拉黑」按钮**；
7. 点「取消拉黑」→ 提示「已取消拉黑，可以继续聊天」，输入框恢复可用；
8. 回数据库看：`blocks` 那条记录 `status` 变 `inactive`，会话 `status` 变 `active`。

### 方式 B：单账号控制台造数（务必把「对方」造出来）

> ⚠️ **这里有个坑，旧版指南写错了，按旧的做一定会失败。**
> 只把会话 `status` 改成 `blocked`、`blockedBy` 填自己 openid，
> 而 `participantIds` 里仍然只有你自己 —— 会话里根本没有第二个人，
> `unblockUser` 当然推不出对象，就会弹「无法确定要取消拉黑的用户。」。
> 页面顶部显示默认昵称「同车旅客」+「旅」字头像，就是 `peerOpenid` 为空的信号。

正确做法：

1. 云开发控制台 → 数据库 → `conversations`，找到你的测试会话（没有就先发帖、
   从帖子详情点「联系发布人」进一次聊天，会自动生成一条）；
2. 记下 `participantIds` 里你自己的 openid；
3. 给这条记录的 **`participantIds` 和 `participantOpenids` 两个数组都补一个假但一致的
   对方 openid**，例如 `test_peer_openid_001`（两个字段都要改，代码两个都读）；
4. 往 `blocks` 集合**新增一条记录**：
   ```json
   {
     "blockerId": "<你的 openid>",
     "blockerOpenid": "<你的 openid>",
     "targetId": "test_peer_openid_001",
     "targetOpenid": "test_peer_openid_001",
     "conversationId": "<这条会话的 _id>",
     "status": "active",
     "reason": "单账号验证"
   }
   ```
5. 把会话 `status` 改成 `blocked`、`blockedBy` 填**你自己的 openid**；
6. 重新编译 → 进聊天页：**通过标准**是顶部「已拉黑」+「取消拉黑」按钮，
   点下去提示「已取消拉黑」，输入框恢复。对方名字仍显示「同车旅客」是正常的
   （假 openid 没有 users 资料）；
7. 反向验证：把 `blockedBy` 改成 `test_peer_openid_001`，并把 blocks 记录的
   `blockerId` / `targetId` 对调 → 重新编译 → 应显示「被拉黑」且**没有**按钮。

> 新版本对「只有自己」的会话也做了兜底：直接点「取消拉黑」会弹
> 「已恢复会话 / 当前会话里只有你自己…已直接恢复会话状态」，不会再卡死。
> 但这只是清理脏数据，**不等于验证了完整的双账号解除流程**。

> 若聊天页顶部出现「云函数 getMessageList 尚未更新到最新版本」的提示，
> 说明云端是旧版：右键 `cloudfunctions/getMessageList` → 上传并部署，即可。

## 八、双账号完整链路验收清单（交接文档第 2 项，之前一直没做）

> 这条是交接文档里被高亮的待办：`发帖 → 另一账号可见 → 私信 → 接单 → 确认完成`。
> **必须用两个不同的微信号**（开发者工具里切换账号 / 一台模拟器 + 一台真机），
> 单账号只能验证状态流转，验证不了「另一账号可见」和权限边界。
> 一个板块全部打勾后再开下一个板块。

### 准备

- A、B 两个账号都完成登录，且**绑定同一个车次**（可以不同车厢，帖子只按车次匹配）；
- 两个账号都能在首页看到列表（控制台无 `-502005`、无「读取 posts 集合失败」）；
- 确认 `comments` 集合已建、`comments` 云函数已部署（下面第 5 步的评论验收要用）。

### 1. 发帖（账号 A）

| 检查项 | 通过标准 |
|---|---|
| 正常发布 | 提示「发布成功，同车旅客可见」，返回上一页，`posts` 集合新增一条，`publisherOpenid` 是 A |
| 内容含敏感词 | 前端先拦；绕过前端时云函数返回 `RISK_CONTENT`，页面弹「发布未成功」并**留在本页**，不再显示成功提示 |
| 弱网/断网 | 内容暂存本地，弹「网络不稳定」，联网后由 `app.onShow` 自动补发 |
| 失败不误报 | **重点回归**：发布失败时不得出现「同车旅客可见」的提示，也不得自动返回上一页 |

### 2. 另一账号可见（账号 B）

| 检查项 | 通过标准 |
|---|---|
| 同车次可见 | B 的首页能看到 A 刚发的帖子（只按 `trainNo` 匹配，同车次不同车厢也算） |
| 不同车次不可见 | B 改绑另一个车次后，该帖子不再出现 |
| 未绑定车次 | 不展示任何帖子，而不是展示全平台内容 |

### 3. 私信（B → A）

| 检查项 | 通过标准 |
|---|---|
| 从帖子进聊天 | 点「私信帮TA」创建会话，顶部显示**对方**昵称而不是自己 |
| 发消息 | A 的「消息」页出现会话与未读红点，点进去能看到消息，红点清零 |
| 时间显示 | 聊天页与消息列表的时间与手机当前时间一致，不出现「NaN 天前」 |
| 拉黑回归 | A 拉黑 B → 双方不能互发 → A 退出重进能点「取消拉黑」→ 恢复发消息（第七节） |

### 4. 接单（B 点「我来帮」）

| 检查项 | 通过标准 |
|---|---|
| 正常接单 | 提示「已发起接单申请」，跳到订单详情，`orders` 新增一条 `status: pending_accept`，`conversations` 出现订单会话 |
| **失败不跳页** | **重点回归**：帖子已被锁定 / 自己发的帖子 / 云函数未部署时，弹「接单未成功」并**停在帖子详情页**，绝不出现 `orderId=` 的空订单页 |
| 发布者入口 | A 的「消息」页订单会话卡片上有蓝色「查看订单 · 接受接单 / 确认完成」入口；A 进聊天页顶部也有同样入口 |
| 接受接单 | A 打开订单详情看到「接受接单」按钮（依赖启动时登录写入 `openid`），点后状态变 `in_progress`，帖子变 `locked` |
| 权限 | B 打开同一订单**不应**看到「接受接单 / 确认完成」（只有发布者能操作） |

### 5. 确认完成 + 评论

| 检查项 | 通过标准 |
|---|---|
| 确认完成 | A 点「确认完成」→ 状态 `completed` → 出现「去评价」，信用分按规则增加 |
| 评价 | 双方各能评价一次，`reviews` 集合有记录 |
| 帖子评论 | 任一方在帖子详情页发表评论 → 列表立刻出现、显示正确昵称与时间；另一账号刷新能看到 |
| 评论校验 | 空内容 / 超 200 字 / 含「转账」等敏感词 → 弹「评论未发布」，不写入数据库 |
| 删除评论 | 只有作者（或该帖发布者）能看到「删除」，删除后列表消失，数据库里是 `status: removed` 软删除 |
| 环境一致 | 全程只用原来的云环境 `tonglu-dev-d1g7ykjzt01f2dcf7`，没有新建环境或第二套数据 |

> 任何一步失败，先看 Console 的红色 error 和云函数返回的 `code` / `message`；
> 出现「云函数 X 未就绪，请确认已上传部署」就是云端还是旧代码，回第五节重新上传。

## 十、常见坑速查表

| 现象 | 原因 | 处理 |
|---|---|---|
| 所有数据都查不到 | 导入时选错了目录（用了残留的错误 AppID） | 删掉项目重新导入，认准仓库根目录 |
| 列表为空但不报错 | 集合权限过严，前端读不到 | posts 等改「所有用户可读」 |
| `-502005 collection not exists` | 集合没建 | 按 docs/01 清单创建 |
| 功能改了没变化 | 云函数没重新上传部署 | 右键该云函数 → 上传并部署 |
| 聊天页提示云函数未更新 | getMessageList 云端是旧版 | 同上 |
| **取消拉黑未成功 / 无法确定要取消拉黑的用户** | **会话里只有自己（单账号自测），`participantIds` 没有第二个人** | **按第七节方式 B 补一个对方 openid + 一条 blocks 记录；并重新部署 3 个云函数** |
| 顶部显示「同车旅客 / 旅」 | `peerOpenid` 为空，会话只有自己 | 同上；新版本会额外显示「自测会话」提示条 |
| 弹「没有找到你对该用户的拉黑记录」 | 是对方拉黑了你 | 正常行为，需要对方解除 |
| 改完代码界面没变 | 没清缓存 | 清缓存 → 全部清除 → 编译 |
| **发布失败却提示成功** | 只判断有没有抛异常，没看 `result.ok` | 已修；回归时看是否弹「发布未成功」并留在本页 |
| **点「我来帮」跳到空订单页** | 失败时仍 `navigateTo` 拼接空 `orderId` | 已修；回归时看是否停在本页 |
| **发布者看不到「接受接单 / 确认完成」** | `globalData.openid` 只在聊天页/资料页登录 | 已在 `app.onLaunch` 与订单页加载前登录 |
| **找不到订单确认入口** | 消息页只有进聊天的入口 | 订单会话卡片 + 聊天页顶部都有直达入口 |
| 评论加载/发布失败 | `comments` 集合没建或 `comments` 云函数没部署 | 现有环境新建集合 + 右键上传部署 |
| 评论显示「同车旅客」 | 该 openid 在 `users` 里没有资料 | 正常兜底，不影响功能 |
| Console 里「快速创建索引链接」 | 云开发建议给 `orders.createdAt` 建索引的性能提示 | 不是报错，可点链接一键建索引，也可忽略 |
| Console 里 `[worker] reportRealtimeAction:fail not support` | 开发者工具运行时的已知警告 | 与业务代码无关，真机不出现，忽略即可 |

## 十一、控制台输出怎么判断有没有问题

编译后看开发者工具 Console：

- ✅ **只需要盯红色 error**。黄色 warning 里上述两条都是无害的；
- ❌ 出现 `-502005 database collection not exists` → 集合没建好 / 连错环境；
- ❌ 出现「读取 posts 集合失败」「云服务未连接」→ 云环境或权限有问题；
- ✅ 点一次「取消拉黑」，看 `[unblockUser] 云端返回：`：
  - `version: '2026-11-07.1'` → 云端是最新代码；
  - 没有 `version` → 还是旧云函数，回第五节重新上传部署；
  - `selfOnly: true` + `warning` → 会话只有自己，状态已自动恢复；
  - `code: 'NO_ACTIVE_BLOCK'` → 是对方拉黑你，正常。
- 评论发不出去时看 `comments` 云函数返回：有 `version: '2026-11-08.1'` 说明云端是新代码；
  `COMMENTS_COLLECTION_ERROR` → 集合没建；`RISK_CONTENT` / `COMMENT_TOO_LONG` → 内容被拦，属正常。
