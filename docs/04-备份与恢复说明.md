## 二、出事了怎么办（按严重程度从轻到重）

### 情况 1：改错了代码，想回到备份时的状态

**最简单，一条命令：**

```bash
git checkout v0.1-baseline-2026-10-17 -- .
```

这会用标签里的文件覆盖当前工作区，**不影响提交历史**。

---

### 情况 2：提交乱了，想彻底回到备份状态

```bash
git fetch origin
git reset --hard backup/2026-10-17-baseline
```

⚠️ `--hard` 会**丢弃当前所有未提交的修改**。执行前先确认真的不要了。

如果只是想撤销最近一次提交但保留代码：

```bash
git reset --soft HEAD~1
```

---

### 情况 3：main 分支被 force push 覆盖了

先从远程拉备份分支：

```bash
git fetch origin backup/2026-10-17-baseline
```

然后在 GitHub 网页上恢复 main：

1. 打开 `https://github.com/Dying-wq/tonglu/branches`
2. 找到 `backup/2026-10-17-baseline`
3. 点右侧 `...` → **Set as default** 或者用它新建 main

或者本地操作：

```bash
git checkout main
git reset --hard origin/backup/2026-10-17-baseline
git push origin main --force
```

## 三、怎么确认「现在到底是不是好的」

不要靠看界面判断，**以命令输出为准**：

```bash
cd /d D:\同路微光\campus-mutual-aid-miniprogram-main
git status
```

- 输出 `nothing to commit, working tree clean` → 干净，和提交一致
- 输出一堆 `modified: xxx` → 有未提交的改动

再确认和远程是否同步：

```bash
git status -sb
```

- `## main...origin/main` → 完全同步
- `## main...origin/main [ahead 3]` → 本地领先 3 个提交，还没推
- `## main...origin/main [behind 2]` → 远程有新提交，需要 `git pull`

## 四、怎么防止队友把代码搞坏

备份是事后补救，**预防更重要**。四件事按重要性排序：

### 1. 永远不要用 `git push -f`

这是唯一能真正「抹掉历史」的操作。

```bash
git push -f        ← 绝对不要执行
git push --force   ← 绝对不要执行
```

**force push 会把远程已有的提交直接删掉，别人的工作会消失，且无法通过普通方式找回。**

如果 Git 提示你需要 force push 才能推上去，说明远程有你没有的提交。**正确做法是 `git pull` 合并，不是 force push。**

### 2. 只给队友 Write 权限，不给 Admin

GitHub 加协作者时选 `Write`。Admin 权限可以删仓库、改设置，没必要给。

### 3. 开工先 pull，收工先 push

不 pull 就改，改完推不上去；不 push 就下班，第二天可能忘记。

### 4. 每次确认能跑通了，打一个 tag

```bash
git tag -a v0.2-日期 -m "说明这次做了什么"
git push origin v0.2-日期
```

Tag 是「存档点」，出问题时永远能回到某个确定可用的状态。**这比压缩包可靠得多。**
