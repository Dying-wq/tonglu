# 同路·微光 — 铁路旅客互助微信小程序

一个基于原生微信小程序与微信云开发的铁路旅客互助平台。项目围绕铁路旅途中的微小需求，提供车次-车厢匹配、求助/帮助信息发布、信用分体系、私信、内容审核、举报仲裁、徽章称号、感谢墙等能力。

> 项目定位：面向铁路旅客场景的公益互助平台。平台不托管资金，不接入真实支付，强调同车精准匹配、轻量化信任、文明互助。

## 项目亮点

- **车次-车厢时空匹配**：用户手动绑定车次号和车厢号，系统仅向同车次旅客展示互助信息，到站后自动解除绑定。
- **剩余车程紧急度标识**：求助信息按剩余车程比例显示不同颜色（>50%白色、25-50%浅黄、10-25%橙色、<10%浅红、发布≤5分钟绿色），已解决信息自动下沉。
- **轻量化信任系统**：初始信用分60分，完成帮助+5分，举报属实+3分，虚假信息-10分，被3人举报骚扰-20分，爽约-5分。低于40分限制发布功能。
- **私信保护**：用户间仅通过小程序内私信沟通，不显示手机号、微信号。私信文字仅保留7天，不存储图片。
- **徽章与称号**：热心旅客（首次帮助）、同路先锋（3次）、微光使者（10次永久称号）、旅途记录者（话题打卡）。
- **感谢墙**：展示最近10条公开感谢，昵称匿名化处理。
- **话题打卡**：无门槛话题（如"拍一张窗外风景"），增加内容多样性。
- **内容安全**：敏感词检测拦截，屏蔽词库支持动态更新。
- **举报与申诉**：四类举报理由（诈骗/金钱交易、骚扰、广告、其他），3人举报自动临时封禁24小时，提供申诉入口。
- **不道德绑架**：不主动推送，帮助完全自愿、无压力。

## 核心功能

### 车次绑定与同车匹配

- 用户进入小程序时手动输入车次号、车厢号（座位号可选）
- 系统将用户与"车次-车厢"绑定，有效期至到达终点站后自动解除
- 支持中途修改（换乘或坐错车厢），修改后原绑定失效
- 首页默认只展示同一车次的求助与帮助信息

### 信息流与紧急度排序

- 同一车次内，求助信息默认按发布时间倒序排列
- 剩余车程比例着色：>50%白色、25-50%浅黄色、10-25%橙色、<10%浅红色（紧急）
- 发布时间≤5分钟新增绿色底色（表示新鲜）
- 已标记"已解决"的信息自动下沉至列表底部

### 发布与互助流程

- 支持三种类型：求助、帮助、话题打卡
- 支持图片选择、预览、删除、上传
- 信用分<40分的用户不能发布
- 发布时绑定当前车次信息，仅同车次可见
- 求助者可选择一位响应者"确认帮助"
- 帮助完成后，求助者需在3小时内点击"问题已解决"
- 列车到达终点后自动关闭未确认的求助

### 信用分体系

- 初始信用分：60分
- 加分：完成帮助+5分、举报属实+3分
- 减分：虚假求助/广告-10分、被3人举报骚扰-20分、爽约-5分
- 等级：≥60分全部功能、40-59分仅浏览和私信、<40分仅浏览、≤0分永久封禁

### 私信与消息

- 消息Tab显示未读红点与未读数
- 会话按最后消息时间倒序
- 聊天页展示关联帖子卡片
- 支持文字消息、举报会话/消息、拉黑用户
- 私信文字仅保留7天，不存储图片
- 首次使用弹出隐私提示

### 徽章与称号

- 热心旅客：完成第一次帮助
- 同路先锋：累计帮助3次，头像框变更
- 微光使者：累计帮助10次，永久称号，个人主页特殊背景
- 旅途记录者：发布第一次话题打卡

### 感谢墙

- 展示最近10条公开感谢语
- 昵称匿名化处理
- 求助者确认"已解决"时可填写感谢语

### 举报与管理后台

- 四类举报理由：诈骗/金钱交易、骚扰、广告、其他
- 同一用户被3个不同人举报且理由一致，自动临时封禁24小时
- 提供申诉入口，申诉成功恢复信用分并解封
- 管理后台支持用户、内容、订单、评价、通知、投诉、日志管理

## 本地运行

1. 使用微信开发者工具打开项目根目录。
2. 在 `miniprogram/config.js` 填写自己的云环境 ID。
3. 在云开发控制台创建数据库集合（参见上方集合列表）。
4. 右键 `cloudfunctions` 下的云函数，选择"上传并部署：云端安装依赖"。
5. 点击编译，在开发者工具中预览。
